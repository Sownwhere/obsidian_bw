## 1. 项目概括

实现了一套外骨骼生物关节力矩估计工程链路：从传感器数据配置、CSV 数据加载、TCN 时序模型训练，到 PyTorch、ONNX、RKNN 推理评估。

核心目标是：利用外骨骼和人体传感器时间序列数据，预测目标关节相关输出，例如关节力矩或编码器相关信号，为外骨骼控制和部署验证提供模型基础。



# TCN / ONNX / RKNN 项目总体工作流与数据加载层说明

## 2. 总体工作流
推荐向上级用以下主线说明：
```text
实验配置
  -> 数据加载
  -> 模型训练
  -> 推理验证
  -> 模型导出 ONNX
  -> 转换 RKNN
  -> CSV/图像/ROS2 输出
````
对应代码层级如下：

|层级|作用|代表文件|
|---|---|---|

|Data Loading|读取 CSV，构造模型输入和标签张量|`tcn_dataset_loader.py`, `phase12_dataset_loader.py`, `phase3_dataset_loader.py`|
|Model Architectures|定义 TCN 和 Transformer 模型结构|`temporal_convolutional_network.py`, `time_series_transformer.py`|
|Training|训练、验证、保存 checkpoint|`train_tcn_model.py`, `train_bilateral_tcn_model.py`, `train_transformer_model.py`|
|Inference|加载模型并做推理|`run_tcn_inference.py`, `run_transformer_inference.py`, `run_rknn_inference.py`|
|Conversion / Evaluation|导出 ONNX、转换 RKNN、评估 RMSE|`export_tcn_checkpoint_to_onnx.py`, `convert_onnx_to_rknn.py`, `evaluate_onnx_model_rmse.py`|
|Outputs / Integration|保存预测 CSV、画图、发布 ROS2|`save_*.py`, `plot_*.py`, `publish_*.py`|
|Orchestration|批量运行配置|`run`|
|Utilities|动态加载配置|`config_loader.py`|

## 4. 数据加载层知识点

核心文件包括：

```text
tcn_dataset_loader.py
phase12_dataset_loader.py
phase3_dataset_loader.py
```
数据加载层的主要任务是：
1. 从 CSV 文件中读取原始传感器数据和标签数据。
2. 根据配置文件选择输入通道和预测目标。
3. 完成归一化、左右侧镜像、NaN 过滤等预处理。
4. 将数据转换为模型需要的 PyTorch 张量格式。
5. 对不同长度的 trial 进行 padding，并保留真实序列长度。
---
## 4.1 输入输出张量形状
代码会将 CSV 数据转换为 PyTorch 张量。
典型形状为：
```text
input_data: [N, C_in, T]
label_data: [N, C_out, T]
```
其中：

| 符号      | 含义        |
| ------- | --------- |
| `N`     | trial 数量  |
| `C_in`  | 输入传感器通道数  |
| `C_out` | 模型预测目标通道数 |
| `T`     | 时间序列长度    |

---
### 单个 trial 的数据转换过程
单个 trial 加载时，代码通常会从 DataFrame 中取出指定列，然后执行：
```python
torch.tensor(df[input_names].values).transpose(0, 1).unsqueeze(0)
```
原始 CSV 中的数据形状是：
```text
[T, C]
```
转换后变成模型需要的格式：
```text
[1, C, T]
```
也就是说：
```text
时间在最后一维
通道在中间一维
batch / trial 维度在最前面
```
这符合 PyTorch 中 `Conv1d` / TCN 常用的输入格式：
```text
[batch_size, channels, sequence_length]
```
---

## 4.2 足底压力体重归一化
在 `tcn_dataset_loader.py` 中，足底压力相关输入会除以受试者体重：
```python
df["insole_l_force_y"] /= body_mass
df["insole_r_force_y"] /= body_mass
```
对应公式为：
```text
F_norm = F_raw / m
```
其中：

|符号|含义|
|---|---|
|`F_raw`|原始足底压力或力数据|
|`m`|受试者体重|
|`F_norm`|体重归一化后的输入|

---
### 归一化的意义

不同受试者体重不同，如果直接使用原始足底力数据，模型可能会过度学习个体体重差异。
体重归一化后，模型更容易关注：

- 步态模式
- 运动阶段
- 支撑 / 摆动变化
- 传感器时间序列特征
而不是单纯依赖受试者体重大小。
---
## 4.3 左右侧镜像处理
当配置中：

```python
side == "l"
```
时，部分左侧 IMU 和 COP 信号会乘以 `-1`：
```python
df["foot_imu_l_gyro_x"] *= -1
df["foot_imu_l_gyro_y"] *= -1
df["foot_imu_l_accel_z"] *= -1
...
df["insole_l_cop_z"] *= -1
```
可以理解为坐标系镜像处理：
```text
x'_k = s_k x_k
```
其中：

|符号|含义|
|---|---|
|`x_k`|原始第 `k` 个传感器通道|
|`s_k`|方向修正系数，取 `1` 或 `-1`|
|`x'_k`|统一方向后的输入|

---

### 左右侧镜像处理的意义
左右腿的传感器坐标方向可能天然相反。
例如：
- 左脚 IMU 的某个轴正方向
- 右脚 IMU 的对应轴正方向
在物理含义上可能是镜像关系。
如果不做方向统一，模型会看到两套方向相反的数据分布，学习难度会增加。
镜像处理的目的就是：
```text
让左腿和右腿数据在模型看来处于一致的坐标定义下
```
这样可以提升模型泛化能力，也方便使用同一个模型处理左右侧数据。

---
## 4.4 NaN 时间点过滤
数据加载时会去掉输入或标签中存在 NaN 的时间点。
判断逻辑可以写成：
```text
valid(t) = not_nan(input[:, t]) AND not_nan(label[:, t])
```
保留有效时间点：
```text
X_valid = X[:, valid(t)]
Y_valid = Y[:, valid(t)]
```
---
### NaN 过滤的意义
NaN 数据可能来自：
- 传感器丢包
- 数据同步失败
- Vicon / OpenSim 输出缺失
- 标签计算异常
- CSV 中部分列为空
如果不处理 NaN，训练时可能导致：
```text
loss = NaN
```
或者在评估时导致 RMSE 计算失败。
因此，NaN 时间点过滤可以提高训练和评估的稳定性。

---
## 4.5 不同长度 trial 的零填充
不同 trial 的时间长度可能不一致。
假设每个 trial 的长度分别为：
```text
T_1, T_2, ..., T_N
```
先找到最大长度：
```text
T_max = max(T_1, T_2, ..., T_N)
```
然后对第 `i` 个 trial 做 padding：
```text
X_i_pad = concat(X_i, 0_{C x (T_max - T_i)})
Y_i_pad = concat(Y_i, 0_{C x (T_max - T_i)})
```
同时保留真实长度：
```text
seq_lengths[i] = T_i
```
---
### Padding 的意义
PyTorch 训练时通常需要把多个 trial 组成一个 batch。
但是 batch 中的张量必须具有统一形状，所以需要把短序列补齐到同一长度。
最终可以得到：
```text
input_data: [N, C_in, T_max]
label_data: [N, C_out, T_max]
seq_lengths: [N]
```
---
### 为什么还要保存 `seq_lengths`
虽然短序列被补零了，但是 padding 部分并不是真实数据。
因此，在计算 RMSE 或可视化时，需要忽略 padding 区域：
```text
只计算 t < seq_lengths[i] 的真实时间点
```
否则 padding 的零值会污染评估结果。

---

## 4.6 数据加载层总结
数据加载层的核心作用可以总结为一句话：

> 将不同 trial、不同传感器、不同受试者、不同长度的原始 CSV 数据，统一转换成模型可以直接训练和推理的标准张量格式。

最终输出通常包括：
```text
input_data
label_data
seq_lengths
trial_names
```
其中：

|输出|作用|
|---|---|
|`input_data`|模型输入|
|`label_data`|监督学习标签|
|`seq_lengths`|每个 trial 的真实长度|
|`trial_names`|用于后续保存结果、画图和误差分析|

## 5. TCN 模型知识点
核心文件：
- `temporal_convolutional_network.py`
TCN 由以下部分组成：
1. `Chomp1d`：裁掉卷积 padding 多出来的时间步
2. `TemporalBlock`：两个 1D 卷积层 + 激活 + dropout + 残差连接
3. `TemporalConvNet`：堆叠多个 `TemporalBlock`
4. `TCN`：完整模型，包含 TCN 主干和最后的线性输出层
### 5.1 输入标准化
TCN 前向传播首先做输入标准化：
```python
out = (x - self.center) / self.scale
````
对应公式：
```text
x_norm = (x - center) / scale
```
其中：
- `x`：原始输入张量
- `center`：配置中的中心值
- `scale`：配置中的尺度值
- `x_norm`：标准化后的输入  
    输入标准化的意义：
1. 将不同传感器通道缩放到相对稳定的数值范围。
2. 避免某些数值较大的通道主导模型训练。
3. 提高训练稳定性。
4. 保证训练和推理阶段的数据分布一致。  
    可以理解为：
```text
先把原始传感器数据变成模型更容易处理的标准范围，再送入 TCN 主干网络。
```

### 5.2 膨胀卷积
TCN 中每一层的 dilation 递增：
```python
dilation_size = 2 ** i
```
对应公式：
```text
d_i = 2^i
```
其中：
- `i`：第 `i` 层 `TemporalBlock`
- `d_i`：第 `i` 层的 dilation size  
    膨胀卷积的一般形式：
```text
y_t = sum_{k=0}^{K-1} w_k x_{t - d*k}
```
其中：
- `K`：卷积核大小
- `d`：dilation
- `w_k`：卷积核权重
- `x`：输入序列
- `y_t`：第 `t` 个时间点的输出  
    普通卷积可以理解为连续看最近几个时间点：

```text
x_t, x_{t-1}, x_{t-2}, ...
```
膨胀卷积则是隔着一定间隔看历史信息：
```text
x_t, x_{t-d}, x_{t-2d}, ...
```
当 dilation 随层数指数增长时，例如：
```text
1, 2, 4, 8, 16
```
模型能够看到越来越长的历史窗口。  
膨胀卷积的意义：
1. 增大时间感受野。
2. 让模型能够利用更长时间范围内的历史信息。
3. 不需要显著增加参数量。
4. 非常适合处理时间序列任务，例如步态、力矩、IMU、encoder 和 insole 数据。  
    可以理解为：

```text
TCN 不是只看当前时刻附近的数据，而是通过 dilation 逐层扩大历史观察范围。
```
### 5.3 残差连接
`TemporalBlock` 的输出形式为：
```python
return activation(out + res)
```
对应公式：
```text
h_out = sigma(F(x) + R(x))
```
其中：
- `F(x)`：两层卷积网络输出 
- `R(x)`：残差路径
- `sigma`：激活函数，例如 ReLU  
    如果输入通道数和输出通道数一致：
```text
R(x) = x
```
如果输入通道数和输出通道数不同，则使用 `1x1 Conv` 对齐维度：
```text
R(x) = Conv1x1(x)
```
残差连接的意义：
1. 缓解深层网络训练困难。
2. 减少梯度消失问题。
3. 让模型更容易学习“在原始特征基础上的修正量”。
4. 有助于 TCN 学习长期时序特征。  
    可以理解为：
```text
模型不需要每一层都从零学习完整映射，而是在已有输入特征上学习一个增量修正。
```

### 5.4 TCN 最终输出
TCN 主干输出后接线性层：
```text
Y_hat = Linear(TCN(x_norm))
```
如果输入为：
```text
X ∈ R^{N x C_in x T}
```
则输出为：
```text
Y_hat ∈ R^{N x C_out x T}
```
其中：
- `N`：trial 数量或 batch size
- `C_in`：输入传感器通道数
- `C_out`：预测目标通道数
- `T`：时间序列长度  
    这表示模型会对每一个时间点都输出一组预测值。  
    例如，如果模型任务是预测右腿髋关节力矩：
```text
C_out = 1
```
那么输出可以理解为：
```text
每一个时间点都有一个预测力矩值
```
如果模型同时预测多个关节力矩：
```text
C_out > 1
```
那么输出可以理解为：
```text
每一个时间点都有多个预测目标，例如 hip moment、knee moment、ankle moment
```
### 5.5 TCN 模型结构总结
TCN 的整体数据流可以概括为：
```text
原始输入 X
  -> 输入标准化
  -> 多层 TemporalBlock
  -> 膨胀卷积提取历史时序特征
  -> 残差连接稳定训练
  -> 线性层输出预测值
  -> Y_hat
```
对应代码逻辑可以理解为：
```text
X: [N, C_in, T]
  -> Normalize
  -> TemporalConvNet
  -> Linear per timestep
  -> Y_hat: [N, C_out, T]
```

### 5.6 面向简洁说法


> 这个项目中的 TCN 模型主要用于时间序列预测。输入数据首先会根据配置中的 `center` 和 `scale` 做标准化，然后送入由多个 `TemporalBlock` 堆叠而成的 TCN 主干网络。每个 `TemporalBlock` 包含两层一维卷积、激活函数、dropout 和残差连接。TCN 的关键是使用逐层递增的膨胀卷积，使模型能够在不显著增加参数量的情况下看到更长的历史窗口。最后，模型通过线性层在每个时间点输出对应的预测结果，例如生物关节力矩或外骨骼辅助力矩。

### 5.7 一句话总结

```text
TCN 通过标准化输入、膨胀卷积扩大历史感受野、残差连接稳定训练，并在每个时间点输出预测结果，非常适合处理外骨骼和人体运动相关的时间序列预测任务。
```



## 6. 损失函数和评估指标
训练脚本中使用：
```python
criterion = nn.MSELoss()
````
这一部分主要涉及两个概念：
1. 训练阶段使用的损失函数：`MSELoss`
2. 验证和推理阶段使用的评估指标：`RMSE`
### 6.1 MSE 损失
MSE 的全称是 Mean Squared Error，即均方误差。  
公式：
```text
MSE = (1 / M) * sum_{m=1}^{M} (y_hat_m - y_m)^2
```
其中：
- `y_hat_m`：模型预测值
- `y_m`：真实标签
- `M`：参与计算的样本点数量  
    MSE 的含义是：
```text
先计算每个预测值和真实值之间的误差，再平方，最后对所有误差取平均。
```
训练阶段通过最小化预测值与真实标签的平方误差来更新模型参数。  
在代码中：
```python
criterion = nn.MSELoss()
loss = criterion(outputs, labels)
```
可以理解为：
```text
模型预测值越接近真实标签，MSE 越小；模型预测偏差越大，MSE 越大。
```
MSE 的特点：
1. 对大误差更加敏感，因为误差被平方。
2. 适合连续值回归任务。
3. 在关节力矩预测、传感器时间序列预测中非常常用。
4. 训练时优化 MSE，可以让模型整体预测曲线更接近真实曲线。
### 6.2 RMSE 指标
验证和推理阶段的核心指标是 RMSE。  
RMSE 的全称是 Root Mean Squared Error，即均方根误差。  
公式：
```text
RMSE = sqrt((1 / M) * sum_{m=1}^{M} (y_hat_m - y_m)^2)
```
其中：
- `y_hat_m`：模型预测值
- `y_m`：真实标签
- `M`：参与计算的有效样本点数量  
    RMSE 可以理解为：

```text
先计算 MSE，再对 MSE 开平方。
```
相比 MSE，RMSE 的优点是：
```text
RMSE 的单位和原始标签单位一致。
```
例如，如果标签是关节力矩：
```text
单位：Nm
```
那么 RMSE 的单位也是：
```text
单位：Nm
```
这使得 RMSE 更容易解释模型误差大小。  
代码中会逐个 trial、逐个输出通道计算 RMSE，再做平均：
```text
RMSE_avg = (1 / K) * sum_{k=1}^{K} RMSE_k
```
其中：
- `K`：有效 trial/channel 组合数量
- `RMSE_k`：第 `k` 个 trial/channel 组合的 RMSE  
    也就是说，评估时不是只计算一个整体误差，而是会分别考虑：
1. 不同 trial
2. 不同输出通道
3. 不同预测目标  
    最后再取平均，得到总体性能指标。
### 6.3 忽略模型历史窗口
代码计算 RMSE 时会跳过前 `model_history` 个时间点：
```python
est = estimates[i, j, model_history:seq_lengths[i]]
lbl = labels[i, j, model_history:seq_lengths[i]]
```
对应公式：
```text
t ∈ [H, T_i)
```
其中
- `H = model_history = model.get_effective_history()`
- `T_i = seq_lengths[i]`
- `i`：第 `i` 个 trial
- `j`：第 `j` 个输出通道  
    这样做的原因是：
```text
TCN 或 Transformer 在序列开头缺少足够历史上下文，前若干时间点预测可能不稳定。
```
对于 TCN 来说，模型依赖历史时间窗口进行预测。序列刚开始时，模型还没有看到足够多的历史信息，因此前面的输出可能不可靠。  
所以评估时会跳过前 `model_history` 个时间点，只计算稳定区间内的误差。  
可以理解为：
```text
训练或推理可以从 t = 0 开始，但评估模型真实性能时，要从模型已经拥有足够历史信息的位置开始。
```
### 6.4 输出延迟修正
如果配置中定义了 `model_delays`，代码会对预测和标签做时间对齐：
```python
est = est[delay:]
lbl = lbl[:-delay]
```
对应公式：
```text
y_hat_aligned(t) = y_hat(t + delay)
y_aligned(t) = y(t)
```
其中：
- `delay`：配置文件中定义的延迟步数
- `y_hat_aligned(t)`：对齐后的预测值
- `y_aligned(t)`：对齐后的真实标签  
    这样做的意义是：
```text
某些目标信号可能存在物理延迟、传感器延迟或处理延迟，需要在计算误差前进行时间对齐。
```
例如，在外骨骼系统中，某些信号可能不是完全同步的：
1. 传感器采集有延迟
2. 力矩估计有延迟
3. 控制输出有延迟
4. 数据后处理时可能存在时间偏移  
    如果不进行延迟修正，模型预测曲线和真实标签曲线可能整体错开，导致 RMSE 被错误放大。  
    延迟修正的目的就是：
```text
让预测值和真实标签在时间轴上对应到同一个物理事件。
```
### 6.5 忽略 NaN 和 padding
RMSE 计算只使用有效时间点：
```text
valid(t) = finite(y_hat(t)) AND finite(y(t)) AND t < seq_length
```
最终计算方式：
```text
RMSE = sqrt(mean((y_hat_valid - y_valid)^2))
```
其中：
- `finite(y_hat(t))`：预测值不是 NaN 或 Inf
- `finite(y(t))`：真实标签不是 NaN 或 Inf
- `t < seq_length`：当前时间点属于真实序列，而不是 padding 部分  
    这样做的原因是：
```text
NaN、Inf 和 padding 都不是真实有效数据，不能参与误差计算。
```
如果把 padding 部分也纳入 RMSE，会出现问题：
1. padding 通常是 0，不代表真实标签。
2. 短序列会被大量补零，影响平均误差。
3. 评估结果会偏离真实模型性能。  
    如果把 NaN 或 Inf 纳入 RMSE，也会导致：
```text
RMSE = NaN
```
因此，评估时必须只使用有效数据点。
### 6.6 MSE 和 RMSE 的区别

| 指标       | 用途     | 是否开方 | 单位      | 主要使用阶段    |
| -------- | ------ | ---- | ------- | --------- |
| MSE      | 优化训练损失 | 否    | 原始单位的平方 | 训练阶段      |
| RMSE     | 衡量预测误差 | 是    | 与原始标签一致 | 验证 / 推理阶段 |


```text
MSE 更适合给优化器用，RMSE 更适合给人看。
```
在训练中使用 MSE，是因为它平滑、可导，方便梯度下降优化。  
在评估中使用 RMSE，是因为它和预测目标单位一致，更容易解释误差大小。

### 6.7 损失函数和评估指标总结
整体流程可以概括为：
```text
模型输出预测值
  -> 使用 MSELoss 计算训练损失
  -> 反向传播更新参数
  -> 验证 / 推理时计算 RMSE
  -> 跳过模型历史窗口
  -> 修正输出延迟
  -> 忽略 NaN 和 padding
  -> 得到最终评估结果
```
对应代码逻辑可以理解为：
```text
outputs = model(inputs)
loss = MSE(outputs, labels)
RMSE = sqrt(mean((outputs_valid - labels_valid)^2))
```
其中，`outputs_valid` 和 `labels_valid` 只包含：
1. 跳过历史窗口后的数据
2. 时间延迟对齐后的数据
3. 非 NaN / 非 Inf 的数据
4. 非 padding 的真实序列数据

### 6.8 汇报时的简洁说法

可以这样解释：

> 训练阶段我们使用 MSELoss 作为损失函数，通过最小化预测值和真实标签之间的平方误差来更新模型参数。验证和推理阶段主要使用 RMSE 作为评估指标，因为 RMSE 的单位和真实标签一致，更方便解释模型误差。在计算 RMSE 时，代码会跳过模型开头缺少历史信息的不稳定区间，并根据配置中的延迟参数对预测和标签进行时间对齐。同时，评估过程会忽略 NaN、Inf 和 padding 区域，确保最终误差只反映真实有效数据上的模型性能。

### 6.9 一句话总结

```text
训练时用 MSE 优化模型参数，评估时用 RMSE 衡量预测误差，并通过跳过历史窗口、延迟对齐、过滤 NaN 和忽略 padding 来保证评估结果可靠。
```
