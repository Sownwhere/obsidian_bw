## 1. 核心框架本质区别

### 1.1 ONNX（Open Neural Network Exchange）

**本质定位：** 中间表示格式（IR）

**核心特点：**

- 仅作为模型交换格式，不负责推理执行
- 需要配合runtime使用（如ONNX Runtime、TensorRT）
- 跨平台兼容性强
- 支持动态shape，灵活性高
- 适合开发和调试阶段

### 1.2 RKNN（瑞芯微神经网络处理工具）

**本质定位：** 面向RK NPU的编译器 + runtime

**核心特点：**

- 将模型编译成NPU可执行图
- 强依赖固定shape输入
- 专注于INT8量化优化
- 低功耗、低延迟特性
- 面向嵌入式设备部署

### 1.3 TensorRT（NVIDIA推理优化器）

**本质定位：** 面向NVIDIA GPU/Tensor Core的推理优化器

**核心特点：**

- 高性能GPU加速
- 支持FP16/INT8精度
- 自动kernel fusion优化
- 静态图编译执行
- 深度优化的GPU计算

## 2. 量化技术详解

### 2.1 量化核心动机

**深度学习部署瓶颈：**

- 内存带宽 > 计算能力
- FP32计算开销大
- 功耗高

**量化目标：**

- 提升推理速度
- 降低功耗
- 减少模型体积

### 2.2 量化数学本质

**量化公式：**

```
x_q = round(x / scale + zero_point)
```

**反量化公式：**

```
x ≈ (x_q - zero_point) × scale
```

### 2.3 FP16 vs INT8 对比

| 特性 | FP16 | INT8 |
| ------ |------ |------ |
| 数据类型 | 半精度浮点 | 整数 |
| 数值结构 | 保留浮点结构 | 整数量化 |
| 精度 | 较高 | 相对较低 |
| 计算方式 | 浮点运算 | 整数MAC运算 |
| 硬件支持 | 广泛 | 需专用加速器 |

## 3. INT8性能优势分析

### 3.1 硬件层面差异

**FP32运算特点：**

- 浮点运算复杂
- 需要指数对齐和尾数运算
- 计算单元占用多

**INT8运算特点：**

- 简单整数MAC（乘积累加）运算
- 支持高度并行化（SIMD/Tensor Core/NPU）
- 硬件实现更高效

### 3.2 系统级优势

- **内存访问减少：** 数据体积缩小4倍
- **带宽消耗降低：** 数据传输量显著减少
- **功耗大幅下降：** 整数运算功耗远低于浮点

## 4. 校准（Calibration）技术

### 4.1 校准核心作用

**校准目标：** 估计activation分布范围

**确定关键参数：**

- 量化scale
- 零点（zero-point）
- 裁剪阈值（clipping threshold）

### 4.2 校准常见问题

**主要错误来源：**

1. 训练数据与实际部署数据分布不一致
2. 异常值（outlier）对量化范围的过度影响
3. 校准样本数量不足

## 5. 校准质量保障工程标准

### 5.1 数据分布真实性（最关键）

**必须包含的场景：**

- 多种动作状态（行走、转向、停止）
- 动态变化过程（状态转换）
- 极端情况（快速变化、最大力矩输出）

**核心原则：** 校准数据 ≈ 实际部署轨迹

### 5.2 激活分布稳定性检查

**需要验证的指标：**

- 直方图是否出现长尾分布
- 是否存在异常尖峰
- 不同batch间分布是否一致

**解决方案：**

- 百分位裁剪（如99.9%）
- KL散度方法

### 5.3 校准数据量要求

**经验值参考：**

- CNN模型：500–2000个样本
- TCN/时序模型：完整轨迹（10–50条）
- 控制模型：必须使用完整episode

### 5.4 精度对比验证

**必须进行的验证：**

- FP32与INT8输出的RMSE
- 输出分布偏移检查
- 最坏情况误差分析

## 6. 主流框架校准机制

**RKNN/TensorRT共性机制：**

- 每层activation统计
- 直方图观察器（histogram observer）
- 图优化后再进行校准
- Kernel融合后量化

## 7. 固定长度输入原因

### 7.1 核心技术限制

**静态图编译限制：**

- shape在编译时固定
- 内存需要提前分配
- kernel调度需要预先优化

### 7.2 时序模型处理方案

**可行的处理方式：**

- **截断（truncate）：** 直接截取固定长度
- **滑动窗口（推荐）：** 窗口滑动处理
- **padding（不推荐）：** 填充方式，不适合控制场景

## 8. 工程视角综合对比

| 框架 | 优势 | 适用场景 |
| ------ |------ |------ |
| ONNX | 灵活、跨平台、支持动态shape | 训练/调试/模型交换 |
| RKNN | 低功耗NPU加速、嵌入式友好 | 瑞芯微平台部署 |
| TensorRT | 高性能GPU加速、深度优化 | NVIDIA Orin/Jetson平台 |

## 9. 控制系统关键结论

**重要注意事项：**

- INT8量化对回归/控制任务风险较高
- 控制系统更关注尾部误差而非平均误差
- 量化可能引入偏差漂移（bias drift）

## 10. 核心总结

**量化的本质：**

用低精度离散表示近似高精度连续函数，同时换取速度、功耗和部署效率的综合优化。

**工程实践要点：**

1. 根据硬件平台选择合适的推理框架
2. 量化需要严格的校准流程保障
3. 控制系统对量化误差更敏感
4. 校准数据的质量决定量化效果上限
